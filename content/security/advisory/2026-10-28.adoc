- id: SECURITY-4125
  reporter: Bilishee from the Xmirror Security Team; and, independently, Anthropic
    OSS program
  title: RCE vulnerability in XStream deserialization due to improper `resolves-to`
    attribute handling
  cve: CVE-2026-117612
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H
  description: |-
    Jenkins uses XStream for serialization and deserialization of configuration and build data.
    To protect from common deserialization vulnerabilities, Jenkins uses a custom deserialization filter that only allows deserialization of types defined in Jenkins core or plugins, or explicitly allowed types (https://jenkins.io/jep/200[JEP-200]).
    These vulnerabilities generally rely on behavior defined in `#readResolve` methods that are executed during deserialization.

    The custom XStream converter used by Jenkins 2.587 and earlier, LTS 2.580.1 and earlier does not apply the deserialization filter to classes referenced by the `resolves-to` attribute.
    This allows attackers to instantiate arbitrary types during deserialization, potentially leading to remote code execution.
    To do this, attackers need to have Overall/Read permission, and at least one of the following:

    * a user account (i.e., cannot be anonymous)
    * any set of permissions allowing them to `POST config.xml` (e.g., Item/Configure, View/Configure, Agent/Configure).

    Jenkins 2.588, LTS 2.580.2 applies the deserialization filter to classes referenced by the `resolves-to` attribute.
    Additionally, Jenkins 2.588, LTS 2.580.2 newly uses the XStream type permissions system (in addition to its own custom converters) to enforce allowed types during deserialization.

    NOTE: In case of problems with the addition to the type permission system, administrators can disable it by setting the link:/doc/book/managing/system-properties/#hudson-util-xstream2-suppress_type_permission[Java system property `hudson.util.XStream2.SUPPRESS_TYPE_PERMISSION`] to `true`.
- id: SECURITY-4225
  reporter: Anthropic OSS program
  title: Collection element type check bypass vulnerability
  cve: CVE-2026-117613
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:U/C:H/I:H/A:H
  description: |-
    Jenkins uses XStream for serialization and deserialization of configuration and build data.
    The ability to provide XML documents to XStream is exposed to users who hold the respective */Configure permission, e.g., the item `POST config.xml` API is available with Item/Configure permission.

    XStream by itself does not restrict the types of collection elements after deserialization.
    While some converters in Jenkins restrict collection element types (see link:/security/advisory/2026-06-10/#SECURITY-3707[SECURITY-3707 in the 2026-06-10 security advisory]), not all converters restrict element types.

    In Jenkins 2.587 and earlier, LTS 2.580.1 and earlier this allows attackers with Item/Configure permission to submit a crafted job `config.xml` file that causes a stored cross-site scripting (XSS) vulnerability.

    TIP: On Jenkins 2.539 and newer, LTS 2.541.1 and newer, enforcing link:/doc/book/security/csp/[Content Security Policy protection] mitigates the known impact of this vulnerability.

    Other XSS vulnerabilities, or other vulnerability types stemming from unexpected collection element types, may also be possible.

    Jenkins 2.588, LTS 2.580.2 adds a post-processing step after collection deserialization and confirms all elements are of the expected types.

    NOTE: In case of problems caused by the element type validation, administrators can disable it entirely by setting the link:/doc/book/managing/system-properties/#hudson-util-robustreflectionconverter-skipfieldvalueelementtypec[Java system property `hudson.util.RobustReflectionConverter.skipFieldValueElementTypeCheck`] to `true`.
    Deserialization fails by default if more than 1,000,000 collection or map elements are type-checked during a single operation.
    The limit can be changed by setting the link:/doc/book/managing/system-properties/#hudson-util-robustreflectionconverter-fieldvalueelementchecklimi[Java system property `hudson.util.RobustReflectionConverter.fieldValueElementCheckLimit`] to a different value.
    In case of problems caused by internal state that prevents collection or map fields from being iterated after deserialization, administrators can suppress these errors by setting the link:/doc/book/managing/system-properties/#hudson-util-robustreflectionconverter-acceptnoniterablecollectio[Java system property `hudson.util.RobustReflectionConverter.acceptNonIterableCollections`] to `true`.
- id: SECURITY-4123
  reporter: Jongyeon Lee (2jo); and, independently, Anthropic OSS program
  title: Agent launch command approval bypass vulnerability
  cve: CVE-2026-117614
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H
  description: |-
    Since Jenkins 2.86, LTS 2.89.1 launching agents by running a command on the controller is implemented in the plugin:command-launcher[Command Agent Launcher Plugin] rather than in Jenkins.

    For backward compatibility with older agent configurations, Jenkins 2.587 and earlier, LTS 2.580.1 and earlier converts the launch commands they contain into launchers provided by this plugin.

    This conversion does not check whether the launch command has been approved by an administrator, allowing attackers with Agent/Configure permission to execute arbitrary code in the context of the Jenkins controller JVM.

    Jenkins 2.588, LTS 2.580.2 no longer converts the launch commands in older agent configurations into launchers provided by the plugin:command-launcher[Command Agent Launcher Plugin].
- id: SECURITY-4187
  reporter: Anthropic OSS program
  title: Link following vulnerability allows arbitrary file read
  cve: CVE-2026-117615
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H
  description: |-
    When renaming an item, Jenkins moves its directory on the controller file system, or copies it if it cannot be moved.

    Jenkins 2.587 and earlier, LTS 2.580.1 and earlier follows symbolic links when copying the directory of an item being renamed.

    This allows attackers with Item/Create and Item/Configure permission to read arbitrary files on the Jenkins controller file system, which can lead to remote code execution (see link:/security/vulnerabilities/#reading[Reading Files]).

    Jenkins 2.588, LTS 2.580.2 no longer copies the directory of an item being renamed if it contains symbolic links.
- id: SECURITY-4188
  reporter: Anthropic OSS program
  title: Path traversal vulnerability in agent names
  cve: CVE-2026-117616
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H
  description: |-
    Jenkins 2.587 and earlier, LTS 2.580.1 and earlier provides an HTTP endpoint that loads agents by name without validating the name, so that any `config.xml` file on the controller file system can be loaded, as an agent carrying the name declared in that file.

    This allows attackers with Overall/Read permission to load any `config.xml` file on the controller file system as an agent configuration, replacing the configuration of an existing agent or defining a new agent.
    The name declared in that file also determines where the agent's configuration is written. When this agent is saved, Jenkins overwrites the `config.xml` file at that location, potentially resulting in arbitrary code execution.

    Jenkins 2.588, LTS 2.580.2 no longer allows loading agents by name through HTTP requests.
    Additionally, when agents are loaded by name, it now validates the name and rejects configurations whose declared name differs from the requested name.
- id: SECURITY-4248
  reporter: Samy Medjahed (Ap4sh)
  title: Race condition in artifact extraction allows arbitrary file creation
  cve: CVE-2026-117617
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H
  description: |-
    To prevent writing files outside the target directory, Jenkins refuses to write files through symbolic links when extracting archived artifacts on the controller.

    Jenkins 2.587 and earlier, LTS 2.580.1 and earlier checks for symbolic links in the path of an extracted file only before creating its parent directories, not immediately before writing it, and allows symbolic links in artifacts to replace existing files or empty directories.

    This allows attackers with Item/Configure permission to write files to arbitrary locations on the Jenkins controller file system by archiving artifacts concurrently, e.g., from parallel branches of a Pipeline, which can lead to remote code execution (see link:/security/vulnerabilities/#writing-files[Writing Files]).

    Jenkins 2.588, LTS 2.580.2 checks for symbolic links in the path of an extracted file immediately before writing it, and does not allow symbolic links in artifacts to replace existing files or directories.

    NOTE: This vulnerability has been reported through the link:/blog/2025/12/10/jenkins-bug-bounty-program-yeswehack-european-commission/[Jenkins Bug Bounty Program sponsored by the European Commission].

- id: SECURITY-4249
  reporter: Samy Medjahed (Ap4sh)
  title: XSS vulnerability in handling of agent errors
  cve: CVE-2026-117622
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:U/C:H/I:H/A:H
  description: |-
    To protect against deserialization vulnerabilities, Jenkins restricts the types of objects that agents can send to the controller (https://jenkins.io/jep/200[JEP-200]).

    Jenkins 2.587 and earlier, LTS 2.580.1 and earlier allows agents to send exceptions implementing the https://github.com/jenkinsci/stapler[Stapler] `HttpResponse` interface, and renders them as HTTP responses.

    This results in a cross-site scripting (XSS) vulnerability exploitable by attackers in control of agent processes.

    Jenkins 2.588, LTS 2.580.2 does not allow agents to send exceptions implementing the https://github.com/jenkinsci/stapler[Stapler] `HttpResponse` interface.
    Additionally, Jenkins 2.588, LTS 2.580.2 sets a restrictive `Content-Security-Policy` header on HTTP responses for form fill failures.

    NOTE: This vulnerability has been reported through the link:/blog/2025/12/10/jenkins-bug-bounty-program-yeswehack-european-commission/[Jenkins Bug Bounty Program sponsored by the European Commission].

- id: SECURITY-4122
  reporter: Jongyeon Lee (2jo); and, independently, Anthropic OSS program
  title: Race condition in setup wizard allows creating an administrator account
  cve: CVE-2026-117618
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H
  description: |-
    By default, the initial setup of Jenkins configures the "Jenkins' own user database" security realm and the "Logged-in users can do anything" authorization strategy, and creates an initial user account.
    During the setup wizard, administrators can create a new administrator account, in which case Jenkins deletes the initial account and then creates the new account.

    To prevent administrators from being locked out, the "Jenkins' own user database" security realm provides an HTTP endpoint that allows unauthenticated users to create a user account while no user accounts exist.

    In Jenkins 2.587 and earlier, LTS 2.580.1 and earlier, this HTTP endpoint does not check whether the setup wizard has been completed, resulting in a race condition that allows unauthenticated attackers to create an administrator account while the initial account is being replaced.

    Jenkins 2.588, LTS 2.580.2 checks whether the setup wizard has been completed before allowing the creation of a user account through the affected HTTP endpoint.
- id: SECURITY-4189
  reporter: Anthropic OSS program
  title: Insufficient session expiration vulnerability
  cve: CVE-2026-117619
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N
  description: |-
    Jenkins's "Keep me signed in" feature uses a persistent cookie, known as the "remember me" cookie, to re-authenticate users without requiring them to enter credentials again. The validity of this cookie does not depend on the credentials used to obtain it.

    Jenkins 2.587 and earlier, LTS 2.580.1 and earlier allows requests authenticated using HTTP Basic authentication, including with an API token, to obtain a "remember me" cookie.

- id: SECURITY-4226
  reporter: Anthropic OSS program
  title: Old Data Monitor injection lets users take over administrator accounts
  cve: CVE-2026-117620
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:U/C:H/I:H/A:H
  description: |-
    Jenkins uses XStream for serialization and deserialization of configuration and build data.
    The ability to provide XML documents to XStream is exposed to users who hold the respective */Configure permission, e.g., the item `POST config.xml` API is available with Item/Configure permission.

    When invalid data (e.g., data for a field that no longer exists) is loaded, this is recorded by the "Manage Old Data" feature if the data is being loaded from disk to allow administrators to review and correct any errors.
    It also allows saving the invalid objects again to remove any stored obsolete data.

    In Jenkins 2.587 and earlier, LTS 2.580.1 and earlier, some of the code paths to report invalid data are not restricted to data being loaded from disk.
    This allows attackers with Overall/Read permission to trigger a warning in the "Manage Old Data" feature.
    When an administrator acts on the warning, it can override a Jenkins user account's data with attacker-controlled content.
    On controllers using Jenkins's own user database, this includes the password for that user account, so that the attacker can log in as that user afterwards.

    Jenkins 2.588, LTS 2.580.2 ensures that warnings in "Manage Old Data" can only be triggered when loading data from disk, not from user-submitted XML, preventing attackers from injecting data this way.
- id: SECURITY-4243
  reporter: 'Anthropic OSS program; and, independently, tracenull; and Opr4 (GitHub: Opr4Mp3r)'
  title: Root element restriction bypass in XStream deserialization
  cve: CVE-2026-117624
  cvss:
    severity: High
    vector: CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:N/I:H/A:N
  description: |-
    Jenkins uses XStream for serialization and deserialization of configuration and build data.
    Types storing their configuration in their own files (usually `config.xml` or `build.xml`), like agents, items, or builds, are indicated as such by implementing the Java interface `PersistenceRoot`.

    Since link:/security/advisory/2026-09-02/#SECURITY-3972[SECURITY-3972 in the 2026-09-02 security advisory], Jenkins attempts to prevent objects of types marked as storing their configuration in independent top-level configuration files in Jenkins from being deserialized as nested values in the configuration of other objects.

    Jenkins 2.587 and earlier, LTS 2.580.1 and earlier does not consistently enforce this restriction, allowing attackers to bypass the root element check and potentially inject malicious nested objects.

    As of publication, the confirmed impact of this vulnerability is limited to the creation of new user records (name and display name only), similar to users appearing in SCM logs.
    Notably, no new user accounts with the ability to log in can be created (unlike in link:#SECURITY-4226[SECURITY-4226]).

    Jenkins 2.588, LTS 2.580.2 ensures that objects of types marked as storing their configuration in independent top-level configuration files in Jenkins cannot be deserialized as nested values in other objects, preventing attackers from bypassing the root element check.
