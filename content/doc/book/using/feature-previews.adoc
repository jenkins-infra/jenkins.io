= Enabling feature previews

Jenkins can provide experimental features that are not yet enabled by default.
The available features depend on your Jenkins version and installed plugins.
They may be incomplete or change before they become generally available.

== Enable a feature for your user

To choose which available Boolean features to use in your own account:

. Sign in to Jenkins and open your user menu.
. Select *Configure*, then open *Experiments*.
. For each feature, choose *Enabled*, *Disabled*, or *Default*.
. Save your changes.

*Default* follows the default configured for your Jenkins controller.
If the administrator has not set a default, Jenkins uses the feature's built-in default, which is usually disabled.
Your explicit *Enabled* or *Disabled* choice applies to your account and overrides the controller default.

User-level experiment settings were introduced in link:/changelog/2.395/[Jenkins 2.395].

== Set defaults for a Jenkins controller

Administrators can set a default for a Boolean experiment flag with a Java system property.
This default is used for users who have not explicitly enabled or disabled the feature.
It does not force the setting: users can still choose *Enabled* or *Disabled* for their own account.

Use the flag key shown in the *Experiments* page and append `.defaultValue` to it.
For example, this command sets the default for the *New dashboard page* feature to enabled:

[source,console]
----
java -Dnew-dashboard-page.flag.defaultValue=true -jar jenkins.war
----

Pass the system property before `-jar`.
For a service, container, or orchestrated installation, add the property to the Java options used to start the controller.
The property takes effect after the controller restarts.
See link:/doc/book/managing/system-properties/[Jenkins features controlled with system properties] for general guidance on Java system properties.

The default-value system property was introduced in link:/changelog/2.535/[Jenkins 2.535].
Use one property for each feature you want to enable by default.
