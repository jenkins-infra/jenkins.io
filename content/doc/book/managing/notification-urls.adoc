Notifications about builds, such as emails, Slack messages, or GitHub commit statuses, often contain a link back to Jenkins.
Many plugins build these links with the plugin:display-url-api[Display URL API plugin].
The same links are available to builds in the `RUN_DISPLAY_URL`, `RUN_CHANGES_DISPLAY_URL`, `RUN_ARTIFACTS_DISPLAY_URL`, `RUN_TESTS_DISPLAY_URL`, and `JOB_DISPLAY_URL` environment variables.

These links end in `/display/redirect` and don't point to a particular user interface.
Jenkins decides which user interface to open when someone clicks the link.
This page explains how to choose that user interface, for example to open links in the classic Jenkins pages or in the plugin:pipeline-graph-view[Pipeline Graph View plugin] instead of Blue Ocean.

== How Jenkins chooses where a link opens

When a notification link is clicked, Jenkins uses the first of the following that is set:

. The personal *Notification URL* setting of the user who clicks the link (see <<Setting your personal preference>>).
. The *Default notification URL* setting for all users (see <<Setting the default for all users>>).
. The `JENKINS_DISPLAYURL_PROVIDER` environment variable of the Jenkins controller.
. The `jenkins.displayurl.provider` Java system property of the Jenkins controller.
. A user interface contributed by an installed plugin, such as Blue Ocean or Pipeline Graph View.
. The classic Jenkins pages.

Because of the last two steps, links open in a plugin's user interface as soon as that plugin is installed, unless one of the settings above is configured.
Changing a setting affects existing links too, because the choice is made when the link is clicked.

The following user interfaces are available out of the box or from common plugins:

[cols="1,2,3",options="header"]
|===
| Name in the settings
| Provided by
| Identifier

| Jenkins Classic
| plugin:display-url-api[Display URL API plugin]
| `org.jenkinsci.plugins.displayurlapi.ClassicDisplayURLProvider`

| Pipeline Graph
| plugin:pipeline-graph-view[Pipeline Graph View plugin]
| `io.jenkins.plugins.pipelinegraphview.PipelineGraphDisplayURLProvider`

| Blue Ocean
| plugin:blueocean-display-url[Display URL for Blue Ocean plugin]
| `org.jenkinsci.plugins.blueoceandisplayurl.BlueOceanDisplayURLImpl`
|===

The identifier is only needed for <<Configuration as Code>>, the environment variable, and the system property.
The settings pages list the user interfaces by name.

== Setting the default for all users

Users with the *Overall/Manage* permission can choose where notification links open for all users:

. Navigate to *Manage Jenkins* > *System*.
. In the *Default notification URL* section, select a user interface in the *Notification URL* field.
. Click *Save*.

Select *Default* to remove the setting.
Jenkins then continues with the environment variable, the system property, and the other steps described in <<How Jenkins chooses where a link opens>>.

=== Configuration as Code

With the plugin:configuration-as-code[Configuration as Code plugin], set the same option with the identifier of the user interface:

[source,yaml]
----
unclassified:
  defaultDisplayUrlProvider:
    providerId: "org.jenkinsci.plugins.displayurlapi.ClassicDisplayURLProvider"
----

== Setting your personal preference

Each user can choose where notification links open for them, overriding the default for all users:

. Click your name in the top right corner, then click *Account*.
. In the *Notification URL* field, select a user interface.
. Click *Save*.

Select *Default* to use the default for all users again.

== Using an environment variable or system property

Instead of the default for all users, the user interface can also be set when starting the Jenkins controller, with the identifier from the table above.
For example, to open notification links in the classic Jenkins pages, set the `JENKINS_DISPLAYURL_PROVIDER` environment variable, or pass this Java system property:

[source,sh]
----
-Djenkins.displayurl.provider=org.jenkinsci.plugins.displayurlapi.ClassicDisplayURLProvider
----

See link:/doc/book/managing/system-properties/[Jenkins Features Controlled with System Properties] for how to set system properties.
The settings in the user interface take precedence over the environment variable and the system property.
