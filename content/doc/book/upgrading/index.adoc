This chapter explains how to upgrade an existing Jenkins installation to a newer version.
For new installations, see link:/doc/book/installing/[Installing Jenkins].

Upgrade Jenkins with the same method you used to install it.
For example, if you installed Jenkins with a Linux package manager, also upgrade it with that package manager, as described in link:linux/[Linux].
Replacing the `jenkins.war` file of a package installation with a downloaded copy leaves the package manager unaware of the new version, and the next package upgrade replaces that file again.

== Before upgrading

. Back up the Jenkins home directory, so that you can return to the previous version if the upgrade causes problems.
See link:/doc/book/system-administration/backing-up/[Backing-up/Restoring Jenkins].
. Read the changes between your version and the new version in the link:/changelog-stable/[LTS changelog] or the link:/changelog/[weekly changelog].
When upgrading an LTS release, also read the link:/doc/upgrade-guide/[LTS upgrade guide], which describes the changes that need attention.
. Check that the new Jenkins version supports the Java version installed on the controller, agents, and CLI clients.
Upgrading Jenkins does not upgrade Java, and Jenkins does not start on an unsupported Java version.
Agents and CLI clients running an unsupported Java version cannot connect to the upgraded controller.
See link:/doc/book/platform-information/support-policy-java/[Java Support Policy] for the Java versions that each Jenkins version requires.
. Upgrading restarts Jenkins, which interrupts running builds.
To let running builds finish first, go to *Manage Jenkins* > *Prepare for Shutdown*.
Jenkins then stops starting new builds, and you can upgrade when the running builds have finished.

== After upgrading

. Check that Jenkins reports the new version in *Manage Jenkins* > link:/doc/book/managing/about-jenkins/[About Jenkins].
. Check for plugin updates in *Manage Jenkins* > *Plugins* > *Updates*, and install the ones you need.
See link:/doc/book/managing/plugins/[Managing Plugins].
