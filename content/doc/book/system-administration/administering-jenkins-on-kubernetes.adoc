= Administering Jenkins on Kubernetes

Running Jenkins on Kubernetes involves administering both Jenkins and the
Kubernetes resources that host it. Cluster networking, storage, security, and
deployment tooling vary between environments, so adapt examples to the
policies and services provided by your cluster administrator.

If you are setting up Jenkins on Kubernetes, start with the
link:/doc/book/installing/kubernetes/[Kubernetes installation guide]. This
page collects the operational topics to consider after installation.
Treat the installation guide's sample manifests as starting points: review
their permissions and storage settings against your cluster's security and
data-retention requirements before applying them in production.

== Configure the controller

The controller stores Jenkins configuration and coordinates builds. Use the
link:/doc/book/managing/casc/[Configuration as Code] plugin to keep supported
controller settings in a version-controlled YAML file. Plugin configuration
may require plugin-specific settings and credentials; consult each plugin's
documentation for its requirements.

If the controller image needs additional tools or preinstalled plugins, build
and maintain a custom image using the
link:/doc/book/installing/docker/[Jenkins Docker installation guidance]. Keep
the image definition and plugin versions under version control so the
controller can be recreated consistently.

== Configure access and networking

Plan how users, API clients, and agents reach the controller. For public HTTP
access, configure the ingress or reverse proxy to preserve Jenkins' required
request headers and WebSocket connections. See the
link:/doc/book/system-administration/reverse-proxy-configuration-with-jenkins/[reverse
proxy configuration guides] and the
link:/doc/book/system-administration/reverse-proxy-configuration-troubleshooting/[reverse
proxy troubleshooting guide].

Grant the controller only the Kubernetes permissions it needs. The
link:/doc/book/using/using-agents/[agent documentation] and
link:/doc/book/pipeline/syntax/[Pipeline syntax reference]
describe ways to run builds in Kubernetes; review the Kubernetes plugin
documentation for the permissions needed by its configured cloud and pod
templates.

== Manage agents and capacity

The link:../managing/nodes[Nodes and Clouds] page covers Jenkins agent
management. For dynamically provisioned Kubernetes agents, configure the
Kubernetes cloud and pod templates through the
link:https://plugins.jenkins.io/kubernetes/[Kubernetes plugin]. Set resource
requests and limits for controller and agent workloads according to the
capacity and scheduling policies of your cluster.

== Protect controller data

Jenkins state is stored in `JENKINS_HOME`. Ensure the controller uses durable
persistent storage appropriate for your Kubernetes environment, and plan how
to recover that data if a pod or node is lost. Follow the
link:/doc/book/system-administration/backing-up/[Jenkins backup and restore guide];
it explains which controller files to protect and how to handle the controller
key separately.

== Monitor and upgrade

Monitor both Jenkins and the Kubernetes resources it depends on. The
link:/doc/book/system-administration/monitoring/[Jenkins monitoring guide]
covers Jenkins-side monitoring; use your cluster's monitoring tools for pod,
node, and storage health.

Before upgrading Jenkins, review the
link:/doc/upgrade-guide/[Jenkins upgrade guides] for release-specific actions.
Update the controller image and any deployment chart or manifests through the
same process used to manage the rest of your Kubernetes workloads, and verify
that persistent data remains available after the controller restarts.
